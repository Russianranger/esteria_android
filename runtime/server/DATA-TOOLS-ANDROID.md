# Composed data tools on Android

This is a distinct provider from the original four-tool server profile. It uses
the two ordered readers plus the unchanged vmap assembler and mmap generator.
`ServerDataToolsSetup` accepts only APK-owned, source-qualified ARM64 metadata,
the exact original navigation configuration, all four paired program identities
and the required Ubuntu runtime identity. Installation is streamed/cached into a
separate immutable generation and never changes imported client files or saves.

`ServerDataToolSelection` writes the exact compact sorted JSON/newline bytes used
by the Python setup helper. Its six file roles, client471/serverf35 revisions,
configuration and ordered-source receipt cannot be substituted by caller labels.
The canonical Python fixture and Java bytes/hash agree; the class does not claim
source qualification from a hash alone. That authority comes from the provider
factory's complete-source/debug/native gates before APK packaging.

Build selection is `-PserverDataToolsProviderDir=<verified-provider>` together
with `-PserverRuntimeProviderDir=<verified-Ubuntu-provider>`. It is mutually
exclusive with `serverExtractorsProviderDir`. The pending source lock currently
contains null unmeasured identities and false source/native flags. Gradle refuses
it before running a provider verifier. No guessed archive or source receipt is
accepted and no launcher action is enabled by this code.

The default Java compile/lint and source/ABI/configuration/closure/canonical-byte
checks pass. Actual positive provider installation, derived native CLI and
Android execution remain separate until the measured factory outputs exist.
The forthcoming retained data operation owner is responsible for the import
lock, native process, timeout/cancellation and completed data binding.
