# Exact source archive retention recovery

The native ARM64 isolated source run `41051669638` at integration `23f727a4`
completed the full offline build, reference tests, source coverage and seven
installed ELF checks. Its original typed qualification and sealed-source receipt
were retained. The final source upload failed because the runner could not
traverse a root-owned `0700` output parent. The archive itself was lost with that
runner. A successful compiler gate alone does not make those missing bytes
available for distribution.

The recovery pin binds that exact failed-upload run/job, its 70,012-byte public
evidence ZIP, both original receipts and the original source archive identity:
24,619,647 bytes, SHA256
`9f76881f06a7c998e0dba9d4a226c623021ed6ad8b87074aa7a861eafbb96d80`.
The immutable inventory contains 266 regular files and 126,583,360 expanded bytes.

The recovery workflow acquires the original 18 MB export, original environment
metadata, exact supplement and old client layout metadata. It checks all 225
recorded integration recipe files at `23f727a4`, regenerates the original source
preparation and runs CMake configuration at the original absolute workspace
paths with the same relevant compiler/development inputs. CMake may run compiler
feature probes; no full server or reference target is compiled. Four missing
generated metadata files must match their original identities, including the
53 MB compile command list and CMake cache. The original `revision.h` custom
target's CMake script is replayed separately in its original script-mode context;
the full build overwrites the configure-time header through that command. Every
other member must also match.

Only an exact match of all members **and the final compressed archive** permits
publication. Original qualification/sealing receipts remain byte-identical; a
separate retention recovery receipt describes this configure-only operation.
A changed generated byte, unsupported origin or different compressed hash stops
publication. This is recovery of the already-qualified artifact, with no new
native-build claim or changed qualification boolean. If configuration cannot
reproduce those bytes, the full native build remains the fallback.

The ordinary isolated and ordered-extractor workflows separately fix publication
parent ownership while preserving `0700`. The native ordered workflow includes
an actual runner-uid traversal regression. No SQL, Android runtime, custom client
data conversion or gameplay qualification follows from these operations.
